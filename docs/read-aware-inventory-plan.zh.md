# Newscope 跑马灯：持久已读与未读库存调度方案

- 日期：2026-11-05
- 状态：**A/B/C/D/E 已完成；150 项自动化测试与 17 项隔离真实浏览器检查通过，正式部署待验收结果确认**
- 适用范围：`dsh-newscope-news-ticker` 与 Newscope 文章查询接口
- 本文保留已确认设计；实现与未部署边界见 [阶段 A](<stage-a-read-state-delivery.zh.md>)、[阶段 B](<stage-b-browser-exposure-delivery.zh.md>)、[阶段 C/D](<stage-c-d-inventory-delivery.zh.md>)、[阶段 E](<stage-e-browser-acceptance.zh.md>)。

## 1. 已确认的产品决策

1. **已读不强求点击。**默认一条新闻获得 **3 次有效可见曝光**后即视为已读；点击可以作为明确的主动已读信号，但不是必要条件。
2. **曝光次数与已读状态都要持久化。**页面刷新、运行行重建或 DSH 重启不能从零重新计数。
3. **插件不触发 Newscope 主动抓取源站。**不调用现有 `POST /api/v1/feeds/{id}/fetch`，也不新增批量抓取任务接口。Newscope 只按自身调度抓源、抽取和评分。
4. **允许插件主动查询 Newscope 已有库存。**未读不足时可以绕过插件缓存，重新读取 Newscope 已入库文章；这只是数据库/API 查询，不是源站抓取。
5. **接受为 Newscope 增加文章查询接口。**新增接口用于评分、时间范围和稳定分页查询，解决现有 RSS 固定最新 100 条的窗口限制。
6. **库存调度顺序固定：**标准未读 → 一级放宽未读 → 二级放宽未读 → 已读重播。任何较高层出现新未读时，重新取得播放权。
7. **放宽不永久修改用户配置。**每次根据当前文章和已读状态动态计算档位；新高质量新闻到达后可自动回到标准档。

## 2. 目标与非目标

### 2.1 目标

- 已读新闻不再混入普通未读播放。
- 用户无需点击，重复获得若干次真实可见机会后即可自动消耗新闻。
- 未读不足时及时检查 Newscope 是否已有新入库文章。
- 当前质量层未读耗尽后，逐步放宽评分和时效，而不是突然展示低质量旧闻。
- 所有放宽层仍不足时，以明确标记的已读重播补足，避免跑马灯长期空白。
- 页面刷新、内容重排和多轮模型运行尽量保持视觉连续。

### 2.2 非目标

- 不判断用户是否真正注视屏幕，不做眼动或注意力追踪。
- 不替 Newscope 管理源站，不改变其抓取周期、源列表、正文抽取或评分流程。
- 不解析 Newscope 管理页面 HTML，不直接读取 Newscope SQLite。
- 不向聊天 Session 写消息，不注册模型工具，不把新闻注入模型上下文。
- 首版不追求多设备同步；已读状态以同一 DSH Host 的持久化数据为准。

## 3. 核心概念

### 3.1 文章稳定键

新增 Newscope 查询接口后，优先使用 `newscope:<articleId>` 作为稳定键。规范化 URL 与带来源命名空间的 GUID 作为兼容别名；旧 RSS 路径缺少文章 ID 时以规范化 URL 兜底。

稳定键不得包含：

- 翻译后的标题；
- 当前评分或所在档位；
- 分类、曝光权重或显示顺序；
- 本次响应中的数组下标。

已读状态不随翻译、评分变化或档位迁移而重置。若 URL 与文章 ID 都改变，则按新文章处理。

### 3.2 一次有效可见曝光

“出现在返回的 `items` 中”或“被创建为 DOM”不算曝光。一次有效曝光必须同时满足：

1. 页面处于前台，`document.visibilityState === 'visible'`；
2. 跑马灯本身可见，未处于卸载、隐藏或移出页面的状态；
3. 文章进入跑马灯的实际裁剪视口，而非仅存在于循环轨道的屏外部分；
4. 有效可见宽度达到阈值，并连续保持约 **1 秒**，防止 DOM 抖动和快速掠过被误计数；
5. 同一次进入视口只计一次，必须离开后才允许下一次计数；
6. 同一文章在同一轮循环中至多计一次，正常组与 `aria-hidden` 克隆组合并处理。

有效可见宽度初始建议为：

```text
min(文章实际宽度, 跑马灯窗口宽度的 50%, 160 CSS px)
```

这样短标题需要较完整地出现，长标题和窄窗口也不会永远无法形成有效曝光。1 秒停留和宽度阈值是实现防抖动参数，首版只需将“已读所需曝光次数”暴露为用户设置。

### 3.3 已读

- 默认 `readAfterExposures = 3`。
- 第 3 次有效曝光由 Host 成功持久化后，文章形成 `readAt`，此后不再进入普通未读池。
- 点击、中键打开或手动标记可以直接形成已读，但不是自动已读的必要条件。
- 点击不代替曝光计数口径；内部仍可分别保存 `readReason = exposure | open | manual`。
- 重播已读文章不会清除 `readAt`，也不会把它重新伪装成未读。

该语义代表“文章已经提供过多次可见机会”，不声称证明用户实际阅读了全文。

## 4. 总体架构

```text
Newscope 自身定时抓源、抽取、评分
                │
                ▼
Newscope 文章元数据分页 API（新增）
                │
                ▼
DSH Host：候选超集缓存 + 持久已读/曝光状态 + 库存状态机
                │
        GET news.json
                ▼
DSH Web：可见曝光检测、批量事件上报、跑马灯安全重排
                │
        POST read-events
                ▼
DSH Host 持久化曝光次数与已读状态
```

Host 是已读状态和库存计算的权威来源。浏览器不自行用 `localStorage` 另建一套互相冲突的已读真相。

## 5. 持久化与事件协议

### 5.1 每篇文章保存的状态

```text
articleKey / aliases
exposureCount
firstReadAt / lastReadAt / readReason
lastShownAt
```

`lastShownAt` 用于重播时优先选择最久未出现的文章。曝光事件可以同时更新该时间，无需为每次动画帧写盘。

持久化要求：

- 使用插件数据目录中的独立文件，不放在易清理的 `~/.cache` 中；
- 按 Newscope 实例命名空间隔离；
- 原子写入、并发合并和有界事件 ID 去重；
- 开发、测试使用独立临时文件，不污染正式已读数据；
- 只清理已经超出最大重播窗口且长期不在上游出现的记录，不能在正常刷新或重启时丢失状态。

### 5.2 DSH 事件接口

新增同源批量接口，例如：

```http
POST /plugins/dsh-newscope-news-ticker/read-events
```

请求示意：

```json
{
  "events": [
    { "type": "exposure", "eventId": "浏览器生成的 UUID", "articleKey": "newscope:123" },
    { "type": "open", "eventId": "另一个 UUID", "articleKey": "newscope:456" }
  ]
}
```

规则：

- 浏览器按约 1 秒批量上报，页面隐藏或卸载时用有限次 `keepalive` 尝试补交；
- Host 以 `eventId` 幂等，网络重试不能把一次曝光算成两次；
- `exposure` 原子增加次数，达到阈值时同事务形成已读；
- `open` 与手动已读幂等，不重复增加曝光次数；
- 只有 Host 持久化成功的状态才进入浏览器的 confirmed 集合；
- 失败事件保留为有界 pending 队列并退避重试，不能静默把未确认状态当成永久已读；
- 写接口限制批次大小、字段长度和请求体大小，并沿用同源/跨站写入保护。

多标签页首版不要求实时锁步：Host 合并所有事件，其他标签页在下一次快照中同步已读状态。同一文章在不同标签页发生的独立有效曝光可以分别计数；事件重试不得重复计数。

## 6. 已读后的界面连续性

采用“**立即记账，延迟安全移除**”：

1. 曝光或点击事件立即进入上报队列；
2. 正在视口中的文章不突然消失；
3. 它离开视口后的下一次安全重排再移出普通轨道；
4. Host 后续快照默认滤除已读，浏览器再按 confirmed 已读集合过滤一次；
5. 已确认但仍在旧轨道中的文章，不因旧快照竞态重新加入未读池。

内容更新时从“只保存像素位置”升级为：

- 优先锚定当前文章稳定键；
- 当前文章仍存在时保持其相对位置；
- 当前文章被过滤时选择相邻的下一篇未读；
- 找不到锚点时才使用有界像素偏移或新列表起点。

循环副本与正常项共享文章状态，不得各算一次曝光。

## 7. 未读库存状态机

### 7.1 初始档位

| 层级 | 默认条件 | 进入条件 |
| --- | --- | --- |
| L0 标准池 | 评分 ≥ 7，时效 ≤ 48 小时 | 默认 |
| L1 一级放宽 | 评分 ≥ 6，时效 ≤ 72 小时 | L0 未读为 0 |
| L2 二级放宽 | 评分 ≥ 5，时效 ≤ 168 小时 | L1 未读也为 0 |
| 重播池 | 已读文章 | L2 未读不足以达到目标库存时补足 |

这些值是首版默认配置，不应散落为不可调整的魔法数。L0 继续以用户的 `minScore/maxAgeHours` 为基准，放宽层作为独立的库存策略配置。

### 7.2 水位

初始建议：

```text
targetInventory = 30
lowWatermark = 10
readAfterExposures = 3
```

- 当前最高优先层未读低于 10：立即重新查询一次 Newscope 已有库存，但仍不进入更低档。
- 当前档未读大于 0 但低于目标：保留当前档，不为了凑满 30 条而提前混入下一档。
- 当前档未读为 0：使用已有候选超集进入下一档，无需等待 Newscope 下次抓源。
- L2 未读不足 30：先放全部 L2 未读，再以重播补足。
- 连重播候选也不存在：返回空列表并隐藏跑马灯，保留原生运行状态行。

### 7.3 优先级与恢复

- 每份快照都从 L0 重新计算，而不是把“已降级”保存成永久模式。
- 新的 L0 未读出现时，下一份快照退出 L1/L2/重播并返回 L0。
- L0 仍为空但出现 L1 新未读时，L1 优先于 L2 和重播。
- 档内沿用现有评分、时间和分类曝光权重调度；跨档则严格执行较高层未读优先。
- 重播优先较高质量层，同层按 `lastShownAt` 最久未播放优先，并保留 `replay: true` 标记。
- 已读历史不因进入重播而清零，曝光阈值也不因档位变化而重置。

## 8. 低水位时只查询，不抓源

低水位触发的是一次 **Newscope 已有文章查询**：

1. 绕过 DSH Host 当前候选缓存 TTL；
2. 通过新增文章 API 获取已经入库且已评分的候选；
3. 重新应用已读过滤和库存状态机；
4. 若没有新增，恢复普通刷新节奏。

必须有单飞和短防抖（建议 30 秒），防止多个标签页或批量事件造成重复查询。这里不需要 15 分钟源站抓取冷却，因为插件根本不会触发源站抓取。

明确禁止：

```text
POST /api/v1/feeds/{id}/fetch
POST /api/v1/feeds/fetch
任何 fetch-jobs 批量抓取接口
```

Newscope 自己的 scheduler 仍按现有配置独立运行。插件重复查询到相同库存是正常结果，不应因此反复加大请求频率。

## 9. Newscope 新增文章查询接口

建议新增：

```http
GET /api/v1/articles
```

首版能力：

```text
min_score
published_after
limit（有服务端上限）
cursor
```

响应示意：

```json
{
  "items": [
    {
      "id": 123,
      "guid": "source-guid",
      "title": "标题",
      "url": "https://example.com/article",
      "score": 8.2,
      "publishedAt": "2026-11-05T07:00:00Z",
      "topics": ["finance"],
      "feed": { "id": 2, "title": "Example Feed" }
    }
  ],
  "nextCursor": "opaque-cursor-or-empty"
}
```

接口约束：

- 默认只返回跑马灯所需元数据，不返回正文或富文本；
- 只返回已分类、已评分文章；
- 使用 `(publishedAt, id)` 稳定倒序和游标，避免新文章插入时 offset 分页重复或漏项；
- `nextCursor` 为空表示耗尽；
- 限制每页数量和总查询成本，错误参数返回明确的 400；
- 保持 Newscope 现有同源安全边界；
- 不改变 RSS、现有管理页面或调度器行为。

Host 每次取“所有档位所需的最宽候选超集”，当前默认即评分 ≥ 5、时效 ≤ 168 小时，分页拉取后在本地划分 L0/L1/L2。不要为三个档分别重复请求。

旧 RSS 可在过渡期保留为兼容回退，但必须返回 `capabilities.history = false`。由于 RSS 固定最新 100 条，回退模式不得宣称支持完整的时效放宽和历史重播。

## 10. DSH 快照响应

在现有 `news.json` 上增加库存与已读元数据，例如：

```json
{
  "items": [],
  "pool": {
    "tier": "L0 | L1 | L2 | L2+replay | replay | empty",
    "unreadCount": 0,
    "targetInventory": 30,
    "lowWatermark": 10
  },
  "readVersion": 123,
  "exposureStates": {},
  "capabilities": { "history": true },
  "stale": false,
  "service": "ok"
}
```

`exposureStates` 只需覆盖当前浏览器仍需显示的文章，避免每次下发完整已读历史。`readVersion` 用于识别旧响应和事件确认竞态。

设置页可以显示：

- 当前档位与有效筛选条件；
- 当前档未读数量；
- 最近一次 Newscope 查询时间；
- 是否处于历史能力受限的 RSS 回退；
- 已读所需曝光次数。

不再展示“正在补抓源站”之类的状态，因为该行为已被明确排除。

## 11. 缓存与故障语义

- 正常快照继续使用 `refreshMinutes` 缓存；低水位查询只绕过一次缓存，不永久缩短全局刷新间隔。
- Newscope 查询失败时，使用最后一份成功的候选超集，并重新应用最新已读过滤；不要返回已经被旧快照重新污染的未读列表。
- 已读事件写入失败不等于 Newscope 不可用，两类错误应分别报告。
- 已读持久化文件损坏或不可写时，不静默宣称已读已保存；保留原生 UI 和可重试事件，并记录明确错误。
- 候选为空与查询失败必须区分：前者可进入下一档或重播，后者只能使用旧缓存并标记 stale。
- 可选翻译和语义去重沿用现有限额；已读键在翻译前确定，翻译失败不得改变文章身份。

## 12. 分阶段执行计划

### 阶段 A：Host 持久已读与事件协议

范围：

- 实现稳定键、曝光计数、已读记录和原子持久化；
- 新增批量幂等 `read-events` 接口；
- 当前 RSS 快照先增加已读过滤和曝光状态；
- 不实现放宽和重播，不触发任何源站抓取。

验收：曝光/已读跨重启保留，事件重试不重复，失败不会静默确认，已读项不再进入下一份普通快照。

### 阶段 B：浏览器有效曝光与安全移除

范围：

- 实现实际裁剪视口检测、前台判断、1 秒防抖和每轮计数；
- 合并正常项与克隆项；
- 批量上报、pending 重试和 confirmed 集合；
- 已读延迟移除与当前文章锚定。

验收：只装载 DOM 不计数，后台不计数，同一出现不重复计数，第 3 次有效出现后才已读，刷新后继续原计数，当前阅读内容不突然消失。

### 阶段 C：Newscope 分页元数据 API

范围：

- 新增稳定游标、评分和时间过滤；
- 返回文章 ID 与必要元数据，不返回正文；
- DSH Host 改为拉取最宽候选超集，旧 RSS 仅作受限回退。

验收：翻页无重复/漏项，新文章插入仍保持游标稳定，参数和页大小有边界，调度器与源站配置零变化。

### 阶段 D：库存档位与已读重播

范围：

- 实现 L0/L1/L2、低水位即时查询、目标库存和重播；
- 每份快照动态恢复较高优先层；
- 返回档位、未读数、重播标记与历史能力。

验收：低水位不提前降级，当前档归零才进入下一档，L2 不足才补重播，新 L0 未读立即抢占，重播不清除已读。

### 阶段 E：设置、文档与真实验收

范围：

- 增加曝光次数及库存参数设置和状态展示；
- 更新 README、CHANGELOG 和 VERIFICATION；
- 在 web-dev 专用 Session 做真实浏览器验收，确认后再发布正式版本。

验收：真实滚动与刷新、后台/前台切换、Newscope 无新增、故障恢复和多标签页行为符合设计；全程没有对源站抓取接口发起请求。

## 13. 必测边界

1. 文章只在 `items` 或屏外 DOM 中，曝光次数保持为 0。
2. 同一文章正常组与克隆组同时存在，不重复计数。
3. 文章一直停留在视口中，只算一次；离开并再次进入后才增加。
4. 后台标签页、隐藏跑马灯和 DOM 重建抖动不产生有效曝光。
5. 曝光事件重试、页面卸载补交和 Host 重启不会重复或归零。
6. 第 3 次有效曝光成功持久化后才过滤；写盘失败不制造假已读。
7. 点击不是必要条件；若实现点击直接已读，其行为必须幂等。
8. 当前文章被过滤时，轨道不突然跳回第一条。
9. L0 有 1 条未读时不混入 L1；L0 为 0 后才进入 L1。
10. L0/L1 仍有未读时不重播；进入 L2 后，未读不足目标库存时才以重播补足。
11. 重播期间出现新 L0 未读，下一份快照返回 L0。
12. Newscope 返回空库存与请求失败走不同路径。
13. RSS 100 条回退被明确标记为历史能力受限。
14. 多标签页事件合并不产生写文件丢失更新。
15. 自动化中显式断言：插件从未调用任何 Newscope 源站抓取接口。

## 14. 后续可调整但不需要改架构的参数

- 已读所需有效曝光次数（默认 3）；
- 单次曝光的可见宽度与停留防抖（初始 1 秒）；
- 低水位与目标库存（初始 10 / 30）；
- 各档评分与时效（初始 7/48h、6/72h、5/168h）；
- 普通刷新间隔与低水位查询防抖；
- 重播的最大历史窗口与同层排序细节。

以上方案已经排除插件主动抓源，并将新增上游接口收敛为只读文章元数据查询。后续实施应按阶段逐项确认完成，不把阶段文档或接口测试当作真实浏览器验收。

## 已实现

### 有效曝光与播放

- 约 100ms 采样：前台、DOM 已连接、非零尺寸、未被自身/祖先隐藏，且与浏览器视口及 overflow 裁剪祖先相交。
- 单个副本可见宽度达到 min(文章宽度, 跑马灯宽度 × 50%, 160px)，连续保持至少 1000ms 才产生一次曝光；采样可能使实际上报稍晚。
- 正常组、克隆组及同页面多个运行行合并计数，不能相加两个不合格副本的可见宽度。
- 同一轮至多一次；跨轮持续可见仍只计一次。所有副本不再满足资格后，才允许新的完整 dwell，并仍受每轮一次约束。
- 后台、隐藏、跌破几何阈值及真正 DOM 重建会中断未完成 dwell；单纯 ResizeObserver 测量不会虚构新出现。
- hover/focus 冻结滚动，但真实可见的内容仍可形成一次曝光，不因暂停时间长而重复计数。
- 多运行行共享一个时钟；任一行 hover/focus 时共同暂停。隐藏/零宽的主行可把时钟交给可见、可测量的行，保持循环相位与曝光状态。
- 只有真实播放位移绕组才增加 cycle；绕组立即持久化。隐藏/恢复重置帧时钟，不补算后台位移。

### 提交、确认与恢复

- 同源 POST /plugins/dsh-newscope-news-ticker/read-events 提交 exposure/open。点击和中键可立即形成已读，但不是自动计数的前提。
- 约 1 秒合并、单飞、每批最多 100 个事件。网络错误、15 秒超时、429、5xx、JSON/ACK 格式错误以原 eventId 退避重试，间隔上限 30 秒。
- 校验 ACK 的 readVersion、accepted/duplicates 总数及本批每个键的状态；HTTP 200、本地累计或 pending 都不能制造 confirmed。
- Host 的 read=true 才确认已读；默认第 3 次门槛继续由阶段 A Host 配置和持久存储决定。
- sessionStorage 保存同标签页 sessionId、position/cycle、已完成的持续可见锁存、pending 和近期已发 ID。刷新后用同一 pending ID 补交，不制造第二次机会。
- pagehide、隐藏和卸载做有限 keepalive 补交；已有请求保持单飞。卸载后的迟到响应不重建 UI、不启动重试。

### 快照、安全移除和锚定

- readVersion 低于最新确认版本的新闻响应整份忽略，避免旧响应覆盖新轨道。
- POST 确认和快照过滤共用安全移除：可见项保留到所有副本离开，或下一次真实循环边界。
- 快照中缺失的项不推断为已读，也可能只是候选变化；只置为待移除。未确认已读的项在新快照重新出现时取消待移除。
- 重建前保存 articleKey、正常/克隆 occurrence 和相对位置；锚点缺失时按旧顺序选后继，避免跳回首条。
- 缩轨后若保持锚点需要负播放位置，保留临时前导空隙并随播放平滑消耗，不用取模让当前文章跳整组；该过渡偏移也能跨刷新恢复。

## 有界故障语义

- pending 最多 1000 条；满时优先保留已有事件。补交期限为 24 小时，近期 issued ID 最多 5000 个。
- 超期、满队列、终止性 4xx、关闭标签页或 Storage 不可用可能导致机会少计，但绝不据此制造已读。Storage 不可用退化为内存重试；keepalive 不保证成功。
- 已确认计数在 Host 持久化，浏览器只保存投递/播放状态，不维护另一份权威已读历史。
- 阶段 A Host 仅为最近 10000 个事件保证幂等。客户端 24 小时期限不等于永久去重承诺；长期离线或高吞吐超出 Host 窗口时不能宣称 exactly-once。
- 可见性仍是提供了可见机会的几何近似，不能证明用户注视屏幕；不检测其他窗口遮挡或任意覆盖层。
